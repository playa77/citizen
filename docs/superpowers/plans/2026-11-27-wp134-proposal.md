# WP-134 — traffic administrative-offence backend proposal

Status: approved by owner on 2026-11-27: “approved. proceed.”
Baseline: merged WP-133, `origin/main` at `d88b70c` (2026-11-27).

## Outcome and scope

Implement catalog M5 `verkehrsrecht` as an experimental peer module through
the existing module framework. Cover traffic administrative-offence notices,
hearing and witness questionnaires, objection preparation, file-access
preparation, qualified driving-ban timing and register/limitation checks.
Accident damage settlement remains catalog stage 2, outside this package.

Deliver the nine roadmap subpackages: dated primary-source verification,
versioned proposed parameters, deterministic deadlines and calculators,
guarded drafts, intake schema, dossier, DE/EN/de-LS copy, at least 15
synthetic cases, deterministic reports and compliance notices. Retain
draft/proposed review status under D-071. Missing facts and unsupported
regimes require review rather than a definitive result.

## Specific architectural changes proposed

1. Add OWiG, StVG, StVO, BKatV, FeV and supporting StPO source types through
   the existing federal corpus adapter, catalog, retrieval/citation mappings
   and PostgreSQL source-type constraint. Extend the single Alembic chain
   with a guarded downgrade. Verify ordinance annex coverage explicitly;
   paragraph-only scraping must not be represented as complete BKat coverage.
2. Extend the existing shared deadline procedure library with the StPO
   rollover rule needed by OWiG, with statutory provenance and golden date
   tests. Reuse explicit actual-service facts; do not invent postal service
   or assume that a hearing questionnaire starts the objection period.
   This is the reusable procedural capability for later M10; legal-area
   applicability, objection and file-access content stay in module data.

No separate procedure service, new database, dependency, generic workflow
framework or automatic module selection. No open-ended deadline redesign.
Any further material shared extension requires a separate specific proposal.

## Rationale, alternatives and consequences

Recommended: extend the existing corpus and deadline libraries as above.
The catalog explicitly calls for a reusable OWiG procedure library; these
changes provide it within established boundaries. They require a migration,
SDK/core capability version updates, API documentation where affected, and
source/parser/provenance and procedural regression tests.

Alternative: module-only static references and calculator-local procedural
dates. This avoids shared changes but leaves retrieval coverage incomplete
and duplicates the procedure rules needed by M10. A new standalone procedure
service would add infrastructure without a demonstrated need.

## Implementation constraints and acceptance

Verify current official statutes before encoding legal rules. Define source
request pacing and bounded attempts before repeated requests. No embeddings
or deployment corpus population. Parameter-backed sanction lookups must
identify their actual covered entries; do not claim complete BKat coverage
from selected examples. Limitation and register calculations must qualify
interruptions, legal finality, record completeness and applicable regimes;
uncertain cases must not assert expiry or driving entitlement. Distinguish
silence about the allegation from duties concerning personal particulars.

Test service versus issue/hearing dates, weekends/holidays, applicable
procedural rollover, limitation interruptions/unknowns, driving-ban timing
qualifications, sanction-table boundaries, register assumptions, guarded
drafts and source identity. Run focused regressions, all-module validation,
offline dossier/plain evaluation, purpose drift and applicable CI gates using
the existing environment and disposable PostgreSQL 16/pgvector.

Preserve the owner's AGENTS.md edit. Record approved architecture in D-076
and implementation results in the execution plan/module changelog and
existing roadmap records; do not recreate deleted root ledgers. Human
promotion, live inference, frontend work, deployment, commit, push and PR
publication are outside this implementation request. Report actual checks
and limitations without claiming deferred reviews or live quality results.
