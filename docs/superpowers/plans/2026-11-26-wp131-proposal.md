# WP-131 — proposed implementation scope

Status: implementation authorized by the owner's explicit repeated direction after this concrete proposal; see D-073.
Baseline: `origin/main` at `c292f52` (2026-11-26).

## Outcome and boundaries

Implement the catalog's tenant-side Wohnraummietrecht package through the
existing module framework: deterministic deadlines and qualified calculations,
four guarded action drafts, public intake schema, appointment dossier,
DE/EN/de-LS copy and at least 15 synthetic cases. Remain experimental; content
review is deferred under D-071. GUI work, publication, live inference and
deployment corpus population are excluded from this implementation request.

## Specific shared extensions proposed for approval

1. Extend the existing Fristen spec/evaluator and dossier facts additively:
   actual receipt (`zugang`), explicit event/reference dates, calendar-month-end
   anchoring and backwards month offsets. Support module-declared applicability
   qualifications without inferring receipt from a letter date. This enables
   § 558b consent, § 556 billing objections, § 574b hardship objections and
   § 569 cure-period rules. Ordinary termination uses a deterministic module
   calculator for the third-working-day rule and qualified notice periods.
   Missing dates, document types or legal qualifications yield missing-input
   results. Existing SGB and service deadline paths retain their semantics.
   Register BGB rollover only for legally appropriate rules; do not apply a
   generic forward rollover to backwards notice periods.
2. Extend the existing corpus catalog/parser and PostgreSQL source constraint
   with BetrKV, HeizkostenV and state tenancy ordinances, through the single
   Alembic chain. Add bounded source adapters for official state publications
   within the current ingestion service, retaining publication/version evidence.
   No new database, service or dependency. Verify source terms and coverage per
   Land; unresolved coverage must remain explicit.
3. Keep geographic applicability in versioned module parameters: Land,
   municipality identifiers, validity intervals, separate rent-brake and
   rent-increase-cap designations, and official source references. Missing,
   expired or ambiguous coverage produces an unavailable calculation, never an
   assumed nationwide designation. Statutory exceptions and comparison-rent
   qualifications must be confirmed before displaying a qualified ceiling.

The existing SDK calculator, template, prompt, plain-copy and intake-schema
contracts cover the remaining work. Bump module/core contract versions where
the new capabilities require them; align API documentation, disclaimers,
prompt versions and pinned expectations with the delivered change.

## Alternatives and consequences

Recommended: the additive extensions above. They preserve core/module ownership
and allow tenancy deadlines to appear in the existing dossier deadline section.
The cost is a larger shared-contract regression surface and state-source
maintenance; automatic live source coverage cannot be asserted from fixtures.

Alternative: implement only module-owned calculations and preparation content,
leaving unsupported deadlines and ordinance ingestion unavailable. This avoids
shared architectural changes but does not complete WP-131's nine subpackages.

Encoding receipt as administrative Bekanntgabe, treating every month interval
as a fixed number of days, or placing tenancy rules in core services is rejected
because it changes legal semantics or violates existing ownership boundaries.
